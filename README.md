# Glide · 마우스 제스처

우클릭한 채로 방향을 그리고 버튼을 놓으면 브라우저 동작이 실행되는 Manifest V3 확장 프로그램입니다. Chrome, Edge, Brave 등 Chromium 계열용이며 빌드나 npm 설치가 필요 없습니다.

## 설치

1. ZIP을 받았다면 먼저 압축을 풉니다.
2. Chrome은 `chrome://extensions`, Edge는 `edge://extensions`를 엽니다.
3. **개발자 모드 → 압축해제된 확장 프로그램을 로드합니다**를 선택합니다.
4. `manifest.json`이 들어 있는 `mouse-gesture-extension` 폴더를 선택합니다.
5. 기존에 열어 둔 웹페이지를 새로고침합니다. 도구 모음의 Glide 아이콘을 누르면 설정이 열립니다.

설정에서 제스처를 다시 그리거나 추가·삭제하고, 동작과 감도를 바꾼 뒤 **변경사항 저장**을 누릅니다. 저장한 설정은 열려 있는 페이지에도 바로 적용됩니다.

이 저장소가 최신 소스입니다. 빌드 없이 저장소 폴더 자체를 확장 프로그램으로 로드합니다. 이전 `chromium-gestures` 경로에서 옮겨 로드하면 Chromium이 별도의 확장으로 취급하므로, 중복 실행을 피하려면 이전 설치본은 끄세요. 새 경로로 설치한 확장은 설정 저장 공간도 별도입니다. 기존 설치 경로에서 0.2.0으로 업데이트하면 기존 설정은 유지됩니다.

## 제스처 백업과 다른 컴퓨터로 옮기기

1. 기존 컴퓨터의 Glide 설정에서 **제스처 내보내기**를 누르고 `glide-gestures-YYYY-MM-DD.json` 파일을 저장합니다.
2. 새 컴퓨터에 Glide를 설치하고 설정의 **제스처 불러오기**로 그 파일을 선택합니다.
3. 변경된 목록을 확인한 뒤 **변경사항 저장**을 누릅니다.

파일에는 제스처 방향, 실행 동작, 직접 지정한 단축키만 설정 데이터로 들어갑니다. 제스처 사용 여부와 감도는 각 컴퓨터에 그대로 남습니다. 불러오기는 현재 목록을 교체하지만 **변경사항 저장** 전에는 기존 저장 설정이 유지됩니다. 파일은 사람이 읽을 수 있는 JSON이며, 손상되었거나 중복·미지원 제스처가 있으면 적용하지 않고 안내합니다. 같은 파일을 다시 선택할 수도 있습니다.

## 단축키 직접 바인딩

1. **제스처 추가**를 누르고 우클릭한 채로 방향을 그립니다.
2. **실행할 동작**에서 뒤로 가기·탭 닫기 같은 내장 동작을 고르거나, **직접 단축키 입력**을 선택해 `Ctrl+T`, `Ctrl+W`, `Alt+Left`, `Ctrl+Shift+K`, `F`처럼 입력합니다. **키로 입력**을 누른 뒤 원하는 조합을 눌러 기록할 수도 있습니다.
3. 실행 대상 안내를 확인하고 **이 제스처 사용 → 변경사항 저장**을 누릅니다.

기존 제스처도 동작 목록을 **직접 단축키 입력**으로 바꾸면 키를 지정할 수 있습니다. 방향 버튼을 눌러 다시 그릴 때도 단축키를 함께 바꿀 수 있습니다. Ctrl/Control, Alt/Option, Cmd/Command/Meta, Shift를 지원하며, 방향키, 문자·숫자, F1–F24, Space·Enter·Tab·Escape 등도 입력할 수 있습니다. 기록 중 Esc는 취소이고, Escape 자체를 바인딩하려면 문자로 입력합니다. 문장부호를 문자로 지정할 때는 US 키보드 배열을 기준으로 합니다.

브라우저가 먼저 가로채는 `Ctrl+T` 같은 조합은 입력란에 문자로 적으세요. 웹페이지의 키 기록 기능으로 모든 브라우저 예약 키를 가로챌 수는 없습니다.

- **브라우저 동작으로 연결:** Ctrl/Cmd+T·N·W·R, F5, **Shift+F5 / Ctrl·Cmd+Shift+R(강력 새로고침)**, Ctrl/Cmd+Shift+T, Alt+Left·Right, Cmd+[·], Ctrl+Tab·Shift+Tab·PageUp·PageDown, Home·End, Ctrl+Home·End, Cmd+Up·Down, **Ctrl/Cmd + +·-·0(확대·축소·원래 크기)**, **F11(전체 화면)**. Ctrl/Cmd+N은 실제 새 브라우저 창을 열며 시작한 탭의 일반/시크릿 상태를 유지합니다.
- **나머지 조합:** 제스처를 시작한 프레임의 현재 포커스 요소에 `keydown`과 `keyup`으로 전달합니다. 단축키 안내에 **웹페이지 단축키**로 표시됩니다. 사이트의 JavaScript 키 핸들러가 처리해야 하며, 실제 타이핑·시스템 키 입력과는 다릅니다.
- 브라우저 기능은 확장 API로 실행할 수 있는 조합만 위 목록에 등록되어 있습니다. 찾기 바(`Ctrl+F`), 저장 대화상자(`Ctrl+S`), 인쇄 옵션(`Ctrl+P`), 북마크 추가(`Ctrl+D`), 방문 기록·다운로드 페이지처럼 **브라우저 UI를 직접 여는 동작은 확장 API가 없어** 매핑할 수 없고 웹페이지 단축키로 전달됩니다. 화면에 없는 기능을 억지로 흉내 내지 않기 위한 의도된 제한입니다.
- Chrome에서 `Ctrl+F5`는 강력 새로고침이 아니라 **주소창으로 커서 이동**입니다. 강력 새로고침은 `Shift+F5` 또는 `Ctrl+Shift+R`(macOS `⌘+Shift+R`)을 쓰세요. `Ctrl+F5`는 그래서 목록에 넣지 않았습니다.
- 브라우저 API로 연결되지 않는 주소창·메뉴 단축키(`Ctrl+L`, `Ctrl+F` 등), 다른 확장의 단축키, OS 단축키는 실행할 수 없습니다. 웹사이트가 `isTrusted`를 검사하거나 실제 키 입력의 기본 동작이 필요한 경우에도 작동하지 않습니다. 이 제한을 우회하는 debugger 권한이나 별도 실행 프로그램은 사용하지 않습니다.

## 기본 제스처

| 우클릭 + 방향 | 동작 |
| --- | --- |
| ← | 뒤로 가기 |
| → | 앞으로 가기 |
| ↓ | 새 탭 |
| ↓ → | 현재 탭 닫기 |
| ↑ ↓ | 새로고침 |
| ↓ ↑ | 닫은 탭 다시 열기 |
| ↑ ← | 이전 탭 |
| ↑ → | 다음 탭 |
| ↑ | 맨 위로 |
| ↓ ← | 맨 아래로 |

탭 복제와 음소거, 강력 새로고침, 확대·축소·원래 크기, 전체 화면도 동작 목록에서 바로 선택할 수 있습니다. 동작 목록과 제스처 안내에는 브라우저 기본 단축키가 함께 표시되며, 기본 단축키가 없는 탭 복제·음소거는 **기본 단축키 없음**으로 표시됩니다. 최대 64개 제스처, 제스처마다 최대 12방향을 지원합니다. 똑같은 방향의 연속 움직임은 하나로 인식합니다.

- 움직이지 않고 우클릭을 놓으면 일반 메뉴가 열립니다. **Shift + 우클릭**은 제스처를 항상 우회합니다.
- **Esc**, 다른 버튼 클릭, 창 전환은 진행 중인 제스처를 취소합니다.
- 등록하지 않은 제스처는 아무 동작도 실행하지 않습니다.
- 손떨림과 작은 대각선 움직임을 걸러내며, Canvas 궤적을 `requestAnimationFrame`으로 묶어 그립니다. 안내 라벨은 방향이 바뀔 때만 갱신하고, 제스처가 끝나면 캔버스 백킹 스토어까지 반환합니다. 페이지 이벤트 리스너는 제스처가 진행 중일 때만 등록하므로 유휴 상태에서는 마우스 이동·키 입력 경로에 확장 코드가 끼지 않고, 타이머·화면 갱신 루프·캔버스 메모리도 남지 않습니다.
- 스크롤은 제스처를 시작한 위치의 스크롤 영역에 적용하며, 키보드 `Home`/`End`처럼 중간 애니메이션 없이 즉시 이동합니다.

## 범위와 제한

- 브라우저 동작은 확장 API로 직접 실행합니다. 시스템 전체 단축키나 다른 확장 프로그램의 단축키를 임의로 누르는 기능은 포함하지 않습니다.
- 주소창, 탭 바, 새 탭, `chrome://`·`edge://` 설정, 웹 스토어, 브라우저 내장 PDF 뷰어 및 다른 확장 페이지는 브라우저 보안 정책상 동작 대상이 아닙니다. 일반 HTTP/HTTPS 웹페이지와 그 안의 프레임에서 사용합니다.
- 전체화면 HTML 요소에서는 궤적도 해당 요소 안에 표시합니다. 브라우저가 별도 UI로 표시하는 영상 전체화면에서는 동작이 제한될 수 있습니다.
- Windows Chromium의 기본 메뉴 발생 시점을 기준으로 일반 우클릭 메뉴를 유지합니다. 메뉴가 버튼을 누르는 즉시 발생하는 OS에서는 제스처를 위해 메뉴를 억제하므로 **Shift + 우클릭**으로 기본 메뉴를 여세요.
- 프레임을 가로지르거나 브라우저 창 바깥으로 이동할 때의 포인터 전달은 브라우저 동작에 따릅니다. 취소되면 시작한 프레임 안에서 다시 그려 주세요.
- 현재 탭 닫기는 실제 탭을 닫습니다. 입력 중인 내용은 해당 사이트의 닫기 확인 정책을 따릅니다. 닫은 탭 복구는 브라우저가 제공하는 최근 탭 기록을 사용합니다.

## 권한과 개인정보

- `storage`: 이 브라우저의 로컬 설정 저장.
- `sessions`: 닫은 탭 다시 열기.
- HTTP/HTTPS 페이지의 콘텐츠 스크립트: 마우스 입력 감지와 궤적 표시. 페이지 스크립트가 만든 가짜 입력으로는 브라우저 동작을 실행하지 않습니다.

외부 서버 요청, 분석, 계정, 원격 코드, 추가 라이브러리는 없습니다. 방문 기록·페이지 내용·그린 궤적을 저장하지 않습니다. 시크릿 창에서는 브라우저에서 확장 사용을 별도로 허용해야 하며, 닫은 탭 복구는 브라우저의 시크릿 제한을 따릅니다.

## 개발 및 검증

Node.js 18 이상에서 `npm test`로 인식기·설정·단축키 파서·백그라운드 동작 테스트를 실행합니다. 빌드는 필요 없습니다. Playwright가 있는 개발 환경에서는 `PLAYWRIGHT_MODULE`에 모듈의 절대 경로를 지정하고 `node tests/browser.cjs`로 전용 Chromium 프로필을 사용한 통합 테스트를 실행할 수 있습니다.

2026-10-21 검증: Node 테스트 26개 통과. Windows의 ego Chromium 154에서 직접 키 기록, 잘못된 조합 거부, 제스처와 단축키 동시 등록·저장·재로딩, 입력한 Ctrl+T·Ctrl+W의 실제 탭 열기·닫기, 기록한 Ctrl+Shift+K의 포커스 요소 전달, 다른 도메인 iframe의 키 전달, 기록 취소와 기존 설정 유지, 390px 설정 화면을 확인했습니다. 0.2.1에서는 기존 Ctrl+N 바인딩으로 탭이 하나 있는 별도의 일반 브라우저 창이 열리는 것과 기존 설정 보존을 추가 확인했습니다. 0.1.0에서 검증한 우클릭 궤적, 새 탭·닫기·복구, 뒤로·앞으로, 새로고침, 탭 전환, 중첩 스크롤, 다른 도메인 iframe, 일반 메뉴·Shift 우회·Esc 취소, 가짜 입력 거부, 설정 즉시 반영, 감도 변경도 유지합니다. macOS/Linux와 물리 마우스별 체감 지연은 별도로 검증하지 않았습니다. 0.2.2는 제스처 중 라벨 DOM 재생성과 캔버스 메모리 점유를 정리하고, 페이지 이벤트 리스너를 제스처 중에만 등록하도록 바꾼 성능 패치이며, Node 테스트 29개가 통과합니다. 0.2.3은 브라우저 기본 동작 매핑(강력 새로고침·확대·축소·원래 크기·전체 화면)과 확장 리로드 직후 낡은 탭의 `Extension context invalidated` 예외 처리(새로고침 안내)를 추가했고, Node 테스트 31개가 통과합니다. Windows ego Chromium 154에서 `RD` 제스처에 바인딩한 Ctrl+Shift+R이 캐시를 건너뛰는 실제 새로고침으로 동작하고, 확대 0.9→1.0 / 축소 1.0→0.9(DIP 비율), 전체 화면 outerHeight 1040→1080→1040, 설정 14개 규칙 원복, 페이지 오류 0건을 확인했습니다. 같은 페이지를 띄운 채 확장을 다시 로드한 뒤 제스처를 실행해 새 런타임 오류가 0건으로 유지되는 것도 확인했습니다. 0.2.4는 새 제스처 화면이 빈 단축키 오류 대신 동작 선택 안내로 시작하도록 하고(화면 낭독기에는 해당 안내를 연결), 내장 동작을 직접 입력보다 먼저 보여 주며, 데스크톱에서 저장 바를 화면 하단에 고정하고, 한국어 줄바꿈(keep-all)·주요 안내 글자 크기·대비를 개선하고, 모바일에서 잘리던 히어로 그림을 숨기고, 다방향 제스처 진행 중 '계속 그리세요'를 표시합니다. Node 테스트 32개가 통과합니다.
